# Журнал решений

Каждое решение: что решили, почему, что отвергли. Новые записи добавлять сверху.

## 2026-10-31 вечер: бэкенд целиком

**Заявки по webhook.** Как в жизни: заявка живёт в нашей системе со статусами и SLA, подрядчику уходит
POST в его CRM с подписью HMAC-SHA256, статусы возвращаются входящим подписанным webhook. Для демо CRM
подрядчика эмулируется внутри приложения (`/mock/contractors`), в проде на её месте чужой URL.
Telegram оставлен как дополнительный канал уведомления. Решение пользователя.

**Автодиспетчер: Jev + политика.** Живой прогон: протечка → Jev «сантехника, критично, риск ущерба 92%» →
заявка «АкваСервис» без ожидания. Без ключа или сети работает табличный запасной путь.

**Условие по времени суток.** LLM честно отказалась собирать «если ночью», потому что в схеме не было
времени. Добавили условие `time` с окном через полночь, прогон подставляет время внутри окна.

**Ujin.** Публикация сигналов на стенд работает (error=0, 26 сигналов пачкой). Сценарии платформы
(`autoscripts/edit`) отвечают «Ошибочный формат сценария», справочник сигналов сценариев отвечает
«Неправильный запрос». Совпадает с ответом организаторов: сценарии на стенде не работают. Экспорт и
попытка отправки остаются, ответ платформы показываем как есть. Платформа эхом возвращает токен жителя,
вырезаем его из всего, что уходит в UI.

**Интерфейс.** Студию встраиваем в интерфейс УК, всё максимально просто, low friction. Мобильное
приложение после готовности веба: обёртка Capacitor. Решения пользователя.

## 2026-10-31 11:xx Брейншторм и фиксация концепта

**Продукт: один для жителя и УК.** Универсальное приложение с двумя ролями. Отвергли: только для жителя
(повторяет Яндекс и Home Assistant), только для УК (теряем wow для демо). Ресёрч показал, что «квартира плюс
общедомовое с ролями» не делает никто, это наша ниша.

**Киллер-фича: автодиспетчер.** ИИ сам вызывает нужного подрядчика из пула УК при поломке. Убирает цепочку
«житель заметил → позвонил управляющему → управляющий оставил заявку». Обязательны quality gates и уровни
политики, чтобы на каждую мелочь не выезжал наряд. Реализуется как тип действия в движке правил, а не как
отдельная система.

**Прогон и линтер как фундамент.** Ресёрч: тест сценария до внедрения и поиск конфликтов не делает ни один
продакшен-продукт. У нас эмуляторы уже есть в пакете, поэтому это самые дешёвые фичи с самым сильным
аргументом на защите.

**LLM: OpenRouter вместо Claude.** Claude дорогой для продукта. Основная модель через OpenRouter (старт с Qwen3,
меняется переменной конфига). Плюс для защиты: открытая модель, можно развернуть on-prem у УК.
Отвергли локальную модель на MVP: несколько часов на отладку промптов, которых нет.

**Jev для вердиктов.** Не-LLM модель, отдаёт типизированные ответы с вероятностями, около $0,00002 за вызов.
Используем для маршрутизации, серьёзности, риска, дубликатов, ложных тревог, «разовая команда или правило».
Вероятность становится quality gate. Формула: LLM пишет, Jev судит.

**Конфиденциальность: минимизация вместо шифрования.** Наружу уходит только текст правила и обезличенный список
устройств с псевдонимами. Отвергли шифрование и кэширование как ответ: не решают вопрос «что видит модель».

**Веб-приложение, не нативное.** Одна кодовая база, открывается по ссылке, работает на телефоне и большом
экране, удобно для скринкаста и для жюри.

**Единый язык устройств = декларация Ujin.** Не изобретаем свой формат, строим конструктор поверх
`declaration()` из пакета эмуляторов. Жюри от Ujin видит свой формат.

**Свой движок исполнения.** Организаторы подтвердили: платформенные автосценарии на стенде не работают,
нужно делать свой. Экспорт в формат autoscripts оставляем для совместимости.

**Стек: Python + React.** Эмуляторы и клиент Ujin уже на Python, портировать за сутки бессмысленно.
FastAPI поверх их `core.py`, React + Vite на фронте. Отвергли full-TypeScript: пришлось бы переписывать
эмуляторы.
