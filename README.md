# HOMIE AI

Редактор сценариев умного дома для платформы Ujin OS. Житель описывает правило словами, система собирает
его по схеме «когда → если → то», проверяет линтером и прогоном на эмуляторах и только потом включает.
Управляющая компания видит дом целиком: инциденты, заявки подрядчикам, общедомовые правила и песочницу.

- **Житель** (`#/resident`) — мобильный экран: свои устройства, сценарии словами, события.
- **Управляющая компания** (`#/uk`) — кабинет: дашборд, ассистент, инциденты, заявки, устройства, правила,
  песочница эмуляторов и связь с платформой Ujin.

Внутри: FastAPI-бэкенд с эмуляторами устройств, движком правил и автодиспетчером заявок; фронтенд на React.
Стенд Ujin и ИИ необязательны: без них проект запускается целиком на локальных эмуляторах.

## Быстрый старт

Есть два способа. **Docker** — одной командой, ничего не ставить. **Локально** — для разработки,
с горячей перезагрузкой кода.

### Вариант 1. Docker

Нужен [Docker Desktop](https://www.docker.com/products/docker-desktop/) (или Docker Engine + Compose).

```bash
git clone https://github.com/southpepperbaby/ujin-scenarist.git
cd ujin-scenarist
python scripts/make_env.py
docker compose up -d --build
```

Открыть: **http://localhost:8800**

`make_env.py` создаёт `.env` с нужными переменными: без этого файла `docker compose` не запустится.
На Windows, если `python` открывает Microsoft Store, используйте `py scripts/make_env.py`.
Остановить: `docker compose down`.
Данные (устройства, правила, журнал) лежат в томе `data` и переживают перезапуск.

### Вариант 2. Локально

Нужны:

- **Python 3.12** и [uv](https://docs.astral.sh/uv/getting-started/installation/) — менеджер пакетов для бэкенда;
- **Node.js 22** или новее (вместе с npm) — для фронтенда.

```bash
git clone https://github.com/southpepperbaby/ujin-scenarist.git
cd ujin-scenarist
```

Дальше два терминала (в VS Code: Terminal → New Terminal, второй — кнопкой «+»).

**Терминал 1 — бэкенд** (http://localhost:8000):

```bash
cd backend
uv run uvicorn app.main:app --reload --port 8000
```

При первом запуске uv сам поставит Python-зависимости, а бэкенд заведёт демо-дом:
9 устройств квартиры и двора и эталонные правила.

**Терминал 2 — фронтенд** (http://localhost:5173):

```bash
cd frontend
npm install
npm run dev
```

Открыть: **http://localhost:5173**. Запросы `/api` и `/ws` фронт сам проксирует на бэкенд.

> Без бэкенда фронт не падает: включается демо-режим с запасным набором данных и пометкой
> «демо-данные» в шапке. Как только бэкенд поднимется, интерфейс переключится на живые данные сам.

## Настройка

Переменные читаются из файла `.env` в корне репозитория. Образец — [`.env.example`](.env.example),
создать файл можно скриптом `python scripts/make_env.py`. Все переменные необязательны.

| Переменная | Зачем | По умолчанию |
|---|---|---|
| `OPENROUTER_API_KEY` | ИИ: разбор правил словами, ассистент, автодиспетчер для нестандартных аварий. Без ключа это недоступно, остальное работает | пусто |
| `LLM_MODEL`, `LLM_FALLBACKS` | Основная и запасные модели OpenRouter | `google/gemini-3.1-flash-lite` |
| `UJIN_LIVE` | `1` — публиковать сигналы на стенд Ujin, `0` — сухой прогон без сети | `0` |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Дублировать заявки подрядчикам в Telegram | пусто |
| `WEBHOOK_SECRET` | Подпись вебхуков к подрядчикам | демо-значение |
| `ALLOWED_ORIGINS` | Адреса стороннего фронтенда через запятую (CORS) | пусто |
| `DATA_DIR` | Где хранить базу SQLite | `backend/data` |

Чтобы заработал ИИ, получите ключ на [openrouter.ai](https://openrouter.ai/keys), впишите его в `.env`
и перезапустите бэкенд.

### Стенд Ujin (необязательно)

Доступы организаторов (`доступы.json`) в git не лежат. Положите файл в корень репозитория и выполните
`python scripts/make_env.py`: скрипт скопирует его в `secrets/ujin.json` и включит `UJIN_LIVE=1`.
Дальше публикацию на стенд можно включать и выключать в кабинете УК, раздел «Платформа».

## Как устроен проект

```
backend/
  app/            FastAPI: API, движок правил, линтер, автодиспетчер, мост в Ujin, ИИ
  emulators/      эмуляторы устройств Ujin (эталон организаторов) и клиент API платформы
  features/       сценарии проверки правил на Gherkin
  tests/          тесты бэкенда
frontend/
  src/features/resident/   приложение жителя
  src/features/manager/    кабинет управляющей компании
deploy/           nginx и заметки по деплою
docs/             концепт продукта и решения
scripts/          подготовка .env и секретов
```

Путь события: эмулятор делает шаг физики → изменение сигнала уходит в шину событий → движок ловит
фронт триггера, проверяет условия и выполняет действия → журнал, уведомления и заявки уходят в интерфейс
через WebSocket.

Подробнее: [фронтенд](frontend/README.md), [эмуляторы](backend/emulators/README.md),
[деплой](deploy/README.md), [концепт](docs/concept.md).

## Частые проблемы

**Порт 8000, 5173 или 8800 занят.** Значит, проект уже запущен в другом окне или другим способом.
Остановите тот запуск или задайте другой порт: у бэкенда `--port 8001`, у Docker `WEB_PORT=8801` в `.env`.
Если меняете порт бэкенда при локальном запуске, укажите его фронту: `VITE_BACKEND=http://localhost:8001`
в `frontend/.env.local`.

**Windows: бэкенд падает с `ModuleNotFoundError` или `No such file`, хотя файл на месте.**
Путь к папке проекта длиннее 260 символов. Склонируйте проект ближе к корню диска, например в `C:\code\`,
или включите длинные пути в Windows (`LongPathsEnabled`).

**Хочется начать с чистого демо-дома.** Остановите бэкенд и удалите `backend/data/scenarist.db`
(в Docker: `docker compose down -v`). При следующем запуске демо-дом создастся заново.

**Разбор правил словами пишет, что ИИ недоступен.** Не задан `OPENROUTER_API_KEY` в `.env`
или бэкенд не перезапущен после правки.
